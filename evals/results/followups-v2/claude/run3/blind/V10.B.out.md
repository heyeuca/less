There's almost nothing to cut. Every rule is needed for either the animation or the accessibility behavior. The only safe trim is shortening the media query:

```html
<style>@keyframes pulse{to{opacity:.6}}.progress{animation:pulse 2s infinite}@media(prefers-reduced-motion){.progress{animation:none}}</style><p class="progress" role="status">Exporting archive</p>
```

**Changed:**
- `(prefers-reduced-motion:reduce)` is now `(prefers-reduced-motion)`. Written this way, the condition is true for any value except `no-preference`, which today means only `reduce`. Browsers that don't support the feature ignore it either way, so behavior is the same.

**Kept:**
- **`@keyframes pulse` and `animation:pulse 2s infinite`**: this is the progress animation. Removing the duration or `infinite` would change how it behaves.
- **The `prefers-reduced-motion` rule**: this turns the animation off for users who ask for less motion.
- **`role="status"`**: this makes screen readers announce the export progress politely.
- **`class="progress"`**: you could select `[role=status]` instead, but that would style every status element on the page, so I kept the class.

**Not done:**
- **Animating only under `(prefers-reduced-motion:no-preference)`**: this would remove one rule, but browsers that don't support the media feature would lose the animation.
- **Adding `alternate` to smooth the snap back to full opacity**: this would change how the animation looks.
