# Harborline Restore Guide

In this guide, we will explain how to restore a database from a Harborline backup snapshot.

## Table of Contents

- [1. Before You Begin](#1-before-you-begin)
- [2. Restore Steps](#2-restore-steps)
- [3. Verify the Restore](#3-verify-the-restore)
- [4. Roll Back a Failed Restore](#4-roll-back-a-failed-restore)
- [6. Snapshot Retention](#6-snapshot-retention)

## 1. Before You Begin

- Admin access to the Harborline console.
- The `harbor` CLI, version 3.2 or later.
- The ID of the snapshot you want to restore.

> **Warning:** A restore overwrites the target database. Any writes made after the snapshot was taken will be lost unless you complete step 2.3.

## 2. Restore Steps

2.1. Log in to the CLI:
```sh
harbor login
```

2.2. List available snapshots and note the ID you want:
```sh
harbor snapshots list --db orders
```

2.3. Take a safety snapshot of the current state, so you can roll back if needed:
```sh
harbor snapshots create --db orders --tag pre-restore
```

2.4. Put the database in maintenance mode to stop new writes:
```sh
harbor db maintenance on --db orders
```

2.5. Run the restore:
```sh
harbor restore --db orders --snapshot <SNAPSHOT_ID>
```

2.6. Turn maintenance mode off:
```sh
harbor db maintenance off --db orders
```

## 3. Verify the Restore

To verify, run:

```sh
harbor db check --db orders
```

If the check reports errors, do not turn maintenance mode back on manually. Instead, go to section 4 and roll back using the safety snapshot from step 2.3.

## 4. Roll Back a Failed Restore

If something went wrong, you can roll back to the safety snapshot you took in step 2.3:

```sh
harbor restore --db orders --snapshot-tag pre-restore
```

Then repeat step 2.6 to turn maintenance mode off.

## 6. Snapshot Retention

Snapshots are kept according to your plan.

| Plan | Retention | Safety snapshots |
|---|---|---|
| Starter | 7 days | Deleted after 24 hours |
| Team | 30 days | Deleted after 7 days |
| Enterprise | 90 days | Kept until deleted manually |
