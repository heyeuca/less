# v0.3.4 held-out measurement (2026-11-04)

The first run of the held-out protocol (#40): ten unseen cases (H01–H10), two
model families, three runs each, and blind grading by the other family. Run
locally with `python3 evals/measure.py evals/results/0.3.4-heldout --runs 3`.
No API keys were used; both CLIs ran on their logged-in accounts.

| Family | Model | CLI | Graded by |
|---|---|---|---|
| claude | claude-opus-5-5 | Claude Code 2.1.287 | codex (gpt-6.1-sol) |
| codex | gpt-6.1-sol | codex-cli 0.160.0 | claude (claude-opus-5-5) |

Each prompt ran in a fresh process in an empty directory: no tools, skills
disabled, and no user config, rules, or session persistence. Sampling was each
CLI's default. No call failed, so `attempts` is empty in every `freeze.json`.
Raw prompts, replies, blind sheets, keys, and `report.json` are in
[`0.3.4-heldout/`](0.3.4-heldout/).

## Result

`protocol_complete: true`, `all_graded: true`, `absolute_gates_pass: false`.

Totals over three runs, 10 cases each (preserved: 10 cases with protected
spans; removed: 6 cases with removal spans; exact no-op: 4 clean inputs):

| | claude with | claude without | codex with | codex without |
|---|---|---|---|---|
| Protected spans kept | 28/30 | 10/30 | 27/30 | 7/30 |
| Required removals | 18/18 | 15/18 | 18/18 | 18/18 |
| Clean input returned byte-for-byte | 6/12 | 0/12 | 5/12 | 0/12 |
| Meaning preserved (blind grader) | 30/30 | 23/30 | 27/30 | 21/30 |
| Outputs with damage (blind grader) | 0/30 | 15/30 | 3/30 | 15/30 |

With the skill, both families kept far more of the good material and caused
far less damage than the same model without it. Neither passes the absolute
gates, which fail on any single output.

## Why the gates fail

Each with-skill failure, split by cause:

**Real failures (the skill should prevent these)**
- codex H01, all three runs: dropped "It prints something like v22.11.0." The
  grader marked these as damage.
- codex H04 run 2: shortened `いただけますでしょうか` to `いただけますか`,
  lowering the politeness register (M9). The grader didn't flag it.
- codex H06, all three runs: inlined `raw = env.get(...)` into the return. The
  behavior is the same and the grader found no damage, but the input was clean
  and should have come back unchanged.

**Measurement artifacts (the output is right; the check is too literal)**
- H07, both families, all runs: only the final newline is missing. The CLIs
  trim trailing whitespace from the last message, so exact byte equality
  can't pass.
- H06 claude, all runs: the code came back unchanged inside a ```` ```python ````
  fence.
- H01 claude runs 1 and 3: "Run `node --version`." is correct, but the
  protected span starts with a lowercase "run".

Without the artifacts, claude's with-skill outputs have no failures and codex's
have the three above. The protocol was frozen before the run, so these were
not reclassified in `report.json`. The next protocol version should compare
no-ops after trimming trailing whitespace and one wrapping code fence. It
should also start protected spans at a word that can't be capitalized. Write
fresh held-out cases for that run.

## Baseline behavior

Without the skill, both models rewrote clean inputs (0/12 exact no-ops). They
also added commentary ("I removed the repeated 'Run' phrasing…", "Tightened:")
and changed wording such as "roughly" to "about". That is where most of the
baseline damage comes from.

## Absolute keep rules (#34 section 4)

P15, P16, D21, and D22 were run the same way, with the skill pasted, three runs
per family. These are `tune` cases, so this checks the current rules, not
held-out evidence. Raw prompts, replies, and checker results are in
[`0.3.4-sec4/`](0.3.4-sec4/). Only these four cases were run, so that directory
holds only their prompts; its `run.json` still lists every prompt `run.py
prompts` wrote.

| Case | Expected | claude | codex |
|---|---|---|---|
| P15 heading that repeats the title | remove `## Deploying` | kept it 3/3 | kept it 3/3 |
| P16 headings a contents list links to | unchanged | kept 3/3 | kept 3/3 |
| D21 opt-out left with nothing to turn off | remove it with the animation | kept the opt-out 3/3 (animation and keyframes removed) | kept the opt-out 3/3 (same) |
| D22 opt-out that still covers a spinner | keep it | PASS 3/3 | PASS 3/3 |

P16's "kept 3/3" ignores the trailing newline the CLIs trim. Both families
follow the current rules exactly: they keep every heading and every
reduced-motion rule, even when it no longer has a job. The next step is to try
narrower wording ("unless it duplicates its parent heading and nothing links to
it"; "unless no animation or transition remains for it to disable"). Keep it
only if P15 and D21 then pass while P16, D22, and new held-out cases still
pass.

## Limits

- Ten cases, two families, one CLI configuration each. This is evidence, not
  a benchmark.
- The grader is a model and makes mistakes. For example, it didn't flag the
  H04 register change.
- Prompts paste the skill text. Organic runs with the skill installed, and
  trigger runs, are not part of this measurement.
- Claude runs here loaded the account's MCP servers, settings files, and
  auto memory: `--tools ""` removed the built-in tools only. No reply here
  mentions them, but one in the later followups-v2 run, with the same flags,
  does (claude run1 V01 without).
  `measure.json` now adds `--strict-mcp-config`, `--setting-sources ""`, and
  `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`; account-level organization
  instructions still apply. See `followups-lessons.md`.
- H01–H10 are now used. Don't tune on them, and write new held-out cases
  before the next claim.
